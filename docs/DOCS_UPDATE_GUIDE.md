# 📝 Инструкция по обновлению ТЗ и Технического Решения

Этот документ описывает процесс обновления технической документации по мере разработки.

---

## 📋 ОБЩИЕ ПРАВИЛА

### 1. Версионирование

Оба документа должны иметь одинаковую версию:

```markdown
**Версия:** 1.0.0
**Последнее обновление:** 2025-01-22
```

### 2. Частота обновлений

| Тип изменения | Когда обновлять |
|---------------|-----------------|
| **Критические** | Немедленно |
| **Важные** | В конце спринта |
| **Минорные** | Раз в месяц |
| **Косметические** | По накоплению |

### 3. История изменений

В конце каждого документа должна быть таблица:

```markdown
### История изменений

| Версия | Дата | Изменения | Автор |
|--------|------|-----------|-------|
| **1.0.1** | 2025-01-23 | Добавлены тесты | AI |
| **1.0.0** | 2025-01-22 | Initial version | AI |
```

## 🔄 КОГДА ОБНОВЛЯТЬ ТЗ (TECHNICAL_SPECIFICATION.md)

### Обновлять при:

1. **Изменении требований**
   ```markdown
   ## 4. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
   
   ### 4.1.1 Новое требование
   - **Требование:** Описание
   - **Статус:** ✅ Добавлено
   ```

2. **Изменении сроков**
   ```markdown
   ## 13. ЭТАПЫ РАЗРАБОТКИ
   
   ### 13.X Новый этап
   - **Длительность:** X недель
   - **Статус:** ⏳ В работе
   ```

3. **Изменении критериев приемки**
   ```markdown
   ## 14. КРИТЕРИИ ПРИЕМКИ
   
   | Критерий | Старый Target | Новый Target |
   |----------|---------------|--------------|
   | Win Rate | >55% | >60% |
   ```

4. **Изменении архитектуры**
   ```markdown
   ## 6. АРХИТЕКТУРА СИСТЕМЫ
   
   ### 6.1 Обновленная схема
   ```

### Не обновлять при:

- Исправлении опечаток
- Рефакторинге кода
- Изменении форматирования

---

## 🔧 КОГДА ОБНОВЛЯТЬ ТЕХ. РЕШЕНИЕ (TECHNICAL_SOLUTION.md)

### Обновлять при:

1. **Изменении реализации**
   ```markdown
   ## 4. РЕАЛИЗАЦИЯ ФАЗЫ 1
   
   ### 4.1.1 Triple Barrier Method
   
   **Изменения:**
   - Добавлен новый метод optimizeParameters()
   - Улучшена точность на 15%
   ```

2. **Изменении технологического стека**
   ```markdown
   ## 3. ТЕХНОЛОГИЧЕСКИЙ СТЕК
   
   ### 3.2 Backend
   
   | Компонент | Было | Стало |
   |-----------|------|-------|
   | Framework | Express | Fastify |
   ```

3. **Изменении статуса**
   ```markdown
   ## 12. СТАТУС РЕАЛИЗАЦИИ
   
   | Компонент | Было | Стало |
   |-----------|------|-------|
   | Unit tests | 0% | 45% |
   ```

4. **Изменении известных ограничений**
   ```markdown
   ## 13. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ
   
   ### Снятые ограничения
   
   - ~~ML модели — заглушки~~ ✅ Реализованы
   ```

### Не обновлять при:

- Косметических изменениях кода
- Изменении комментариев
- Рефакторинге без изменения функциональности

## 📝 ПРОЦЕСС ОБНОВЛЕНИЯ

### Шаг 1: Определить изменения

```bash
# Посмотреть изменения с последней версии
git diff HEAD~1..HEAD -- packages/
```

### Шаг 2: Обновить ТЗ

Открыть `TECHNICAL_SPECIFICATION.md` и:

1. Обновить версию и дату
2. Добавить изменения в соответствующие разделы
3. Обновить таблицу истории изменений

### Шаг 3: Обновить тех. решение

Открыть `TECHNICAL_SOLUTION.md` и:

1. Обновить версию и дату (должна совпадать с ТЗ)
2. Описать изменения в реализации
3. Обновить статусы
4. Обновить таблицу истории изменений

### Шаг 4: Commit

```bash
git add TECHNICAL_SPECIFICATION.md TECHNICAL_SOLUTION.md
git commit -m "docs: Update ТЗ и тех. решение до v1.0.1

- Добавлены unit тесты (45% coverage)
- Обновлены требования к производительности
- Изменен статус Phase 1 на ✅ Завершено"
```

### Шаг 5: Уведомить команду

```markdown
@channel Обновление документации v1.0.1

Изменения:
✅ Добавлены unit тесты
📊 Обновлены метрики производительности
📝 Изменены требования к безопасности

Документы:
- TECHNICAL_SPECIFICATION.md
- TECHNICAL_SOLUTION.md
```

## 🎯 ШАБЛОНЫ ОБНОВЛЕНИЙ

### Шаблон: Добавление новой функции

**В ТЗ:**
```markdown
### 4.X.X Новая функция
- **Требование:** Описание требования
- **Вход:** Входные данные
- **Выход:** Выходные данные
- **Статус:** ✅ Добавлено в v1.0.1
```

**В тех. решении:**
```markdown
### 4.X.X Реализация новой функции

**Файл:** `packages/.../new-feature.ts`

**Реализация:**
```typescript
export class NewFeature {
  // Код
}
```

**Статус:** ✅ Реализовано в v1.0.1
```

### Шаблон: Изменение требования

**В ТЗ:**
```markdown
### 4.X.X Измененное требование

| Параметр | Было | Стало | Обоснование |
|----------|------|-------|-------------|
| Target | >55% | >60% | Улучшение ML модели |

**Статус:** ⚠️ Изменено в v1.0.1
```

**В тех. решении:**
```markdown
### 4.X.X Соответствие измененному требованию

**Изменения в реализации:**
- Улучшена ML модель
- Добавлены новые фичи
- Увеличена точность на 8%

**Текущий таргет:** >60% ⚠️ Требуется проверка
```

### Шаблон: Исправление бага

**В ТЗ:**
```markdown
## 13. ИЗВЕСТНЫЕ ПРОБЛЕМЫ

### Исправленные проблемы

- ~~Баг #123: Неверный расчет PnL~~ ✅ Исправлено в v1.0.1
```

**В тех. решении:**
```markdown
## 14. ПЛАН ДОРАБОТОК

### Выполненные доработки

| Задача | Было | Стало | Статус |
|--------|------|-------|--------|
| **Баг #123** | Неверный расчет | Верный расчет | ✅ |
```
